# 3D 空間の edge (object-space edges) を CueMol で使える形に仕上げる

CueMol は umbreon の edge を、画面空間の stroke (`--edges`、`edges/screen_vector_edges.cpp` +
`edges/stroke_render.cpp`) だけで描いている。3D 空間の edge (`--obj-edges`、
`ObjectSpaceEdgeOptions`、Method B) は、輪郭線を細い円柱として場面に足し、レイトレーサーに
遮蔽させる方式で、線が途切れにくく、CueMol の OpenGL / WebGL の edge (法線方向に押し出した
裏面の殻) に近い見え方になる。POV-Ray 時代の edge もこの方式だった。umbreon には抽出の
大部分が入っているが、CueMol から使う手前で止まっている。この plan で、CueMol から選べ、
renderer ごとの edge の設定が効く状態まで仕上げる。

対象は umbreon と cuemol2 の両方。umbreon の変更が先で、cuemol2 は `UMBREON_GIT_REF` を
移す PR で追随する。

## 1. 現状

### 1.1 umbreon にあるもの

- 入口: `render/pipeline.cpp` が、`objectSpaceEdges.enable` のとき場面を複製して
  `generateObjectSpaceEdges()` (`edges/object_space_edges.cpp`) で輪郭の円柱を足してから
  トレースする。stroke edge と同時には有効にできない (例外)。
- 抽出:
  - 球と円柱の解析的な輪郭 (`edges/analytic_silhouette.hpp` の `emitAnalyticSilhouettes`。
    球の地平線の輪、円柱の 2 本の側線、端面が見えるときの縁。正射影・透視の両方)。
    隣の立体の内側に入る部分は、線に沿って点を取り全立体に対して内外判定して捨てる
    (`clipAndEmit` / `insideAnySolid`、総当たり)。
  - 三角形 mesh の滑らかな輪郭 (頂点法線の n·v = 0 を面の中で補間)、折れ目 (crease)、
    境界 (border) (`edges/mesh_feature_edges.cpp` の `extractMeshFeatureEdges`)。
  - mesh だけを遮蔽物にした隠線の切り落とし (`visibilityClip`、既定オフ)。
- 線: 半径 `width` (ワールド単位、既定 0.03) の開いた円柱を `ROUND_LINEAR_CURVE` に
  つないで描く (`render/curve_build.cpp`)。端点を共有する円柱は 1 本の折れ線に
  つなぎ、内側の継ぎ目は 1 つの球の掃引になる (重なりで濃くならない)。鎖の両端には
  丸い端が付く。材質は `Material::flatOutline()` (平坦な色)。見え隠れはトレーサーの
  遮蔽、AA は通常の supersample。
- 輪郭の持ち上げ: 球の輪は法線方向に `raise`、mesh の滑らかな輪郭は `raise + width`
  動かす (`analytic_silhouette.cpp` / `mesh_feature_edges.cpp` の `detectSilhouettes`)。
  mesh の境界・折れ目は `raise`。同じ `raise` でも、線の中心の位置が立体の種類で違う。
- 頂点の alpha: mesh の線の端点に頂点の alpha を付けるのは、溶接した頂点に乗る端点
  だけ。滑らかな輪郭が三角形の辺を横切る点 (合成した点) は不透明のまま。さらに、
  既定の経路 (`visibilityClip` オフ) は円柱にするときに端点の alpha を渡さない
  (`makeEdge(s.p0, s.p1, opt, s.group)`)。
- テスト: `tests/test_object_space_edges.cpp` (輪郭の幾何、切り落とし、mesh の各種 edge、
  `render()` への組み込み、stroke との排他)。

### 1.2 足りないもの

1. CueMol から選ぶ手段が無い (cuemol2 は `objectSpaceEdges` を一切設定していない)。
2. 色と太さが場面全体で 1 つ (`makeEdge` が `opt.color` / `opt.width` を使う)。
   renderer ごとの設定 (`Scene::groupEdgeStyle`、edge group) を読まない。edge なしの
   renderer の線も消せない。
3. CueMol の `egtype` の 2 つのモードのうち、silhouette (背景との境だけに線を出す。GL は
   `trigedge_frag.glsl` で `gl_FragDepth = 0.9999`) が無い。
4. 球・円柱の切り落としが総当たり (点の数 × 立体の数)。
5. 半透明 (頂点の alpha は §7 の別タスク): 頂点の alpha による線の薄れ (edge_line2) が、既定の経路では効かず、
   切り落としの経路でも滑らかな輪郭では効かない (§1.1)。group alpha (veil) との
   組み合わせはテストが無い。
6. 別々の鎖が出会う所 (輪郭と境界など) の継ぎ目が閉じているかを確かめていない。
7. edge の円柱が影・AO・GI にどう関わるか (影を落とすか、AO で暗くなるか) を決めて
   いない。
8. `docs/plans/edge-extraction-embree.md` の状態の記述が実装と合っていない。

## 2. 方針

### 2.0 コードの配置 (umbreon)

今は `src/umbreon/edges/` に screen 方式 (stroke) と object 方式のファイルが混ざって
いる (22 ファイル、約 8000 行)。object 方式の実装に入る前に、方式ごとにディレクトリを
分け、両方が使う部分を共通のディレクトリに置く。

- 配置:

  | ディレクトリ | ファイル |
  | --- | --- |
  | `edges/common/` | `screen_projection` (両方式が使う投影)、`mesh_weld.hpp` (bench の mesh 読み込みも使う)、§2.0 の silhouette の深度判定 |
  | `edges/screen/` | `screen_vector_edges`、`screen_edge_classify` / `trace` / `prune` / `geometry`、`screen_edge_common.hpp`、`stroke_edges`、`stroke_render` |
  | `edges/object/` | `object_space_edges`、`analytic_silhouette`、`mesh_feature_edges` (mesh の輪郭・折れ目・境界の抽出)、§2.4 の球・円柱用 BVH |

  - ファイル名の `screen_` などの接頭辞は変えない (git の履歴と grep のため)。
  - `edges/*.hpp` はインストールしない内部のヘッダー (`CMakeLists.txt` の
    INTERNAL の注記) なので、移動は cuemol2 に影響しない。直すのは umbreon の
    `#include`、`CMakeLists.txt` のソース一覧、`src/bench`・`tests` の include、
    docs のパスの記述 (`docs/edges_screen_vector.md`、`docs/api/libumbreon.md` など)。
  - mesh の特徴線の抽出 (`extractMeshFeatureEdges`) を呼ぶのは object 方式だけ。
    screen 方式は G-buffer の深度・オブジェクト ID などを `classifyCracks()` に渡して
    輪郭を抽出する。`screen_vector_edges.hpp` と `tests/test_screen_vector_integration.cpp`
    は `mesh_feature_edges.hpp` を include しているが、抽出の関数は使っていないので、
    移動のコミットで必要なヘッダー (`screen_projection.hpp` など) に置き換え、screen から
    object への依存を作らない。
  - §2.1 の `raise` の定義の統一 (と §7 の頂点 alpha の補間) は、object 方式の mesh の
    抽出に適用する。screen 方式の出力には関わらない。
- 共通にするもの (今回の実装で両方式が同じ規則を使うもの):
  - silhouette モードの背後の深度判定: 背後の物体の view-z を閾値 `outlineFarVz` と
    比べる判定 (`screen_edge_classify.cpp` の `outlineSuppress` の深度の部分) だけを
    `edges/common/` の小さなヘッダーに移し、§2.3 の intersection filter からも同じ
    関数を呼ぶ。両方式で、fog に溶けた奥の物体の扱いがずれない。
  - モード (Full / Outline) の取得は共有しない。screen 方式の `outlineMode()` は
    edge group に変換済みの `objectId` (`id >> 2`) でモード表を引く。object 方式は
    元のセクション ID でスタイル表 (§2.2) を引くので、同じ関数に渡すと別の renderer の
    モードを選ぶおそれがある。各方式が自分の表でモードを取得し、Outline のときだけ
    共通の深度判定を呼ぶ。
- 共通にしないもの: スタイル表 (screen は edge group で画素単位の幅、object は
  セクション ID で Å 単位の半径、§2.2)、見え隠れの判定 (screen は G-buffer の分類、
  object はトレーサーの遮蔽)。仕組みが違い、まとめても共有できる処理がほとんど無い。
- 進め方: 移動だけのコミット (`git mv` と include の書き換え、挙動の変更なし) を最初に
  作り、全テストが通ることを確かめてから機能の変更に入る。移動は機械的な作業で、
  影響は umbreon の中に閉じるので、別のプランには分けない。silhouette モードの判定の
  共通化は §2.3 の実装と同じ段階で行う。

### 2.1 CueMol での切り替えと線の太さ (cuemol2)

- `UmbreonRenderSettings.qif` に edge の方式 `edgeMethod` (`screen` / `object`) を足す。
  既定は当面 `screen` (今の見た目を変えない)。§6 の確認を経て既定を変えるかを決める。
- exporter の `applyRenderSettings()` が `edgeMethod` を `UmbreonDisplayContext` に渡す。
  `object` のとき、`UmbreonDisplayContext` が `strokeEdges` の代わりに
  `objectSpaceEdges` を埋める。renderer ごとの設定は §2.2 の表で渡す。
- 今回の完了条件: console またはスクリプト (`set_render_settings
  settings="umbreon.edgeMethod=object"` など) で方式を切り替え、同じシーン・カメラで
  `screen` と `object` の画像を書き出せること。GUI の選択項目は後続の作業にする。
- 太さ: `eglinew` は Å 単位で、ワールド空間の実際の長さそのもの。POV-Ray の出力に
  合わせて、線 (円柱) の半径を `eglinew` Å にする (太さは `2 * eglinew`)。
- 線の持ち上げ (`raise`): POV-Ray の出力に合わせて、CueMol は `raise = 0.25 * eglinew`
  (半径の 1/4) を渡す。線の内側は面に隠れる。半径分ずらして線全体を面の外に出す案は、
  POV-Ray と比べると線が約 1.4 倍太く、球と stick の接合部の円弧も長く残ったので
  やめた。
  - umbreon では `raise` を「元の輪郭点から線の中心までの変位の、輪郭の単位法線
    方向の成分」と定義し直し、立体の種類によらず同じ意味にする。今は mesh の滑らかな
    輪郭だけ法線方向に `raise + width` 動く (§1.1) ので、そのまま `raise = r` を渡すと
    mesh だけ中心が `2r` 外に出て、面と線の間に隙間ができる。mesh の輪郭の法線方向の
    変位を `raise` に揃える (今の CLI の `--obj-edges` の mesh の輪郭は位置が変わる)。
  - mesh の輪郭には、法線方向の持ち上げとは別に視点方向の補正 (`camBias`、
    `detectSilhouettes`) が掛かる。これは自分の面に隠れないための補正で、輪郭点では
    視線と法線がほぼ直交するので法線方向の成分にはほとんど効かない。`raise` の定義には
    含めない。
  - object 方式では、mesh の輪郭を辺の上に置く (下記) ので自分の面に隠れることがなく、
    この補正は使わない (POV-Ray も使っていない。使うと線が太く見えた)。以下の 2 項目は
    補正を残していたときの経緯。
  - ただし今の補正量 `max(0.5 * width, 0.15 * 平均辺長)` は辺の長さで決まり、線が
    細いと線の太さよりずっと大きく手前へ出る (半径 0.005 Å の線が 0.171 Å 手前に
    出て、本体を完全に覆う不透明な板の上に線が現れた)。POV-Ray は法線方向の持ち上げ
    だけで、視点方向には動かしていない。補正量に線の半径に応じた上限 (線の半径
    程度) を設ける。上限を入れたあと、滑らかな輪郭が自分の面に隠れて途切れないかを
    目視 (段階 1 の手順 4) で確かめ、途切れる場合は上限の倍率を調整する。
  - 目視で GL と比べるときは、同じ線幅の球と滑らかな mesh の両方で、線の内縁が面の
    外周に接するかを見る。
  - mesh の輪郭は、滑らかな輪郭 (頂点法線の n·v = 0) ではなく、POV-Ray と同じく辺の
    両側の面の法線で決める (辺の上に線を置く)。POV-Ray の画像を正解として比べると、
    滑らかな輪郭は角張った mesh の輪郭より内側に来る所があり、線が自分の面に隠れて
    先細り・途切れになった。辺で決めると途切れは無くなり、線の位置も POV-Ray と揃う。
  - 面積 0 の三角形 (リボンの矢じりで断面の幅が変わる所などにできる) は、法線が誤差
    なので輪郭・折れ目・外周の判定に使わず、辺の隣接からも外す。隣接に残すと、その
    法線で面の内側に線が出るうえ、本来の隣の面の枠を奪って線が欠ける。外したことで
    隣が無くなった辺は外周として扱う (POV-Ray もそこに線を描いている)。
- 球・円柱の輪は、円形断面の 3 次 Bézier 曲線で描く。今は 48 分割の折れ線なので、
  分割点の中間では弦が円の内側に入り、線が細いと球に埋まって途切れる (半径 5 Å の
  球で幅 0.01 Å の線)。分割数を増やす・外接させる (`circumscribe`、分割点で線が外へ
  浮く) といった調整をせず、曲線で円そのものを描く。
  - 輪 1 周を、45 度ずつの Bézier 曲線 8 本で描く (円とのずれは半径の 100 万分の 4
    程度で、球の大きさや線の太さによらず無視できる)。単独の球で、中心線を一周する
    3,600 本の光線がすべて線に当たることを確認済み (レビュー)。対象は球の地平線の輪と
    円柱の端面の縁。円柱の側線と mesh の線は今どおり直線 (`ROUND_LINEAR_CURVE`)。
  - Embree の 3 次の round 曲線 (`RTC_GEOMETRY_TYPE_ROUND_BEZIER_CURVE`) は円を曲線に
    沿って掃引した管で、端に球を置かない。接線が連続する円弧どうしは継ぎ目で重ならず、
    閉じた輪は一続きの管になる (直線の曲線のような隣接区間の指定は要らない)。
  - `curve_build.cpp` に Bézier の形状の種類 (primID ごとの表と `GeomKind`) を足し、
    shading 側 (`shadeHit` の振り分け) で扱う。材質・色・セクション ID は直線の線と
    同じ。
  - stick との接合部の切り落としは、今どおり輪に沿って点を取って内外判定し、残す
    角度の区間ごとに Bézier を作り直す (45 度以下の区間に分ける)。管の端にふたが
    無いので、切った端が stick や球の中に隠れることを目視で確かめる。
  - 輪の分割数の指定 (API `edge_types.hpp` と CLI `scene_setup.cpp` の既定 48) は、
    輪には使わなくなる。切り落としの判定で輪に沿って取る点の数としてだけ残すか、
    要らなければ消す (実装時に決める)。既存テストの、分割数を明示して輪の本数を
    数える期待値は、輪が一周閉じること・端面に輪郭ができることを本数に依らず
    確かめる形に直す。

### 2.2 renderer (セクション) ごとの設定 (umbreon)

- `Scene` に、セクションごとの 3D 空間 edge のスタイル表を足す:
  `std::vector<ObjectEdgeStyle> groupObjectEdgeStyle` (色、半径、持ち上げ、
  輪郭・折れ目・境界それぞれの有無、モード (full / outline))。添字はセクション ID
  (球・円柱・三角形が持つ `group`) そのもので、`edgeGroupFor(group)` は通さない。
  表が空なら従来どおり `ObjectSpaceEdgeOptions` の値を使う。
  - CueMol は renderer ごとに固有の `group` を割り当てる。edge group は stroke の
    スタイルの key (画素単位に丸めた幅など) でまとめるので、Å 単位の線幅が違う
    2 つの renderer が同じ edge group に入り得る。セクション ID で引けば、各 renderer の
    `egtype` / `eglinew` / `egcolor` をそのまま使える (POV-Ray もセクション単位だった)。
- stroke 用の `groupEdgeStyle` は画素単位の幅と stroke 固有の項目を持つので、流用せず
  別の表にする。CueMol は renderer の `egtype` / `eglinew` / `egcolor` / crease の角度から、
  両方の表を同じ規則で埋める。
- 抽出は表を引いて、無効のセクションの線を作らない。円柱にはセクションの色と半径を
  載せ、元のセクション ID を引き継ぐ (veil の合成に使う、§2.7)。
- POV-Ray 出力に合わせ、mesh の輪郭抽出では頂点の統合と辺の隣接判定をセクション内で
  行う。別の renderer の面が同じ辺に接していても、その辺は各セクションの境界として
  扱う。生成した線を描画するときの遮蔽はシーン全体で判定する。
- 線描画 (`startLines()`、ワイヤー表示の結合や距離線) に由来する円柱からは輪郭を
  作らない。cuemol2 の exporter は線を通常の円柱に変換する (`convLines(true)`) ので、
  今は線の両側に黒い輪郭が付く。POV-Ray writer は線本体だけを出し、edge の有無で
  画像が変わらない。umbreon の円柱に「輪郭を作らない」印を足し、cuemol2 が線から
  変換した円柱にだけ付ける。同じ renderer の stick には指定どおり輪郭が付く。
  同じ印の円柱は、§2.4 の切り落としの遮蔽物 (総当たりの判定と切り落とし用 BVH の
  登録) からも外す。外さないと、ワイヤーの近くの stick の側線が切られる (POV-Ray では
  切られない)。ワイヤーとの見え隠れは本体の主光線に任せる。

### 2.3 silhouette モード (背景との境だけ) (umbreon)

- GL と POV-Ray の挙動: GL は線の深度を最奥 (0.9999) にして、背景の前にだけ出す。
  POV-Ray は線上の点から視線の奥へ光線を飛ばし、何かに当たる点を捨てていた。
- umbreon では、outline モードのセクションの edge 円柱に印を付け、主光線がそれに
  当たったとき、同じ光線をその先へ延ばして、線と同じセクションの物体に当たるかを
  調べる (別のセクションの物体は通り抜ける)。POV-Ray は輪郭の計算も見え隠れの判定も
  セクションごとで、screen 方式も同じセクションの自己遮蔽だけを消すので、それに揃える
  (1CRN の tube + 一部 ball-and-stick で、どのセクションでも消していたときは tube と
  ball-and-stick の境の線が消えた)。
  当たれば、その edge は無いものとして光線を先へ進める (背景の前でだけ線が残る)。
  - 奥へ延ばす光線は、当たった画素の位置からではなく、その画素が属する線の中心点
    (Embree の曲線パラメータ `u` から求める輪郭上の点) から出す。POV-Ray と同じく、
    線の幅方向では見え隠れが変わらない。画素の位置から出すと、背景が線より狭い隙間
    から見える所で、線の一部の画素だけが残って細い切れ端になった (1CRN の
    ball-and-stick で POV-Ray と比べて確認)。
- 背後の物体の範囲 (far clip と fog): 輪郭を消すのは、背後の物体が「元の主光線の
  far clip 内にあり、かつその view-z が閾値 `outlineFarVz` 以下」のときだけにする。
  - fog でほぼ背景に溶けた奥の物体の前では、手前の物体の輪郭は残すのが意図した
    見え方。fog は後処理なので、ここで捨てた線を後から戻せない。
  - 閾値は screen 方式と同じもの (cuemol2 が `outlineFarDepth` を fog の開始・終了から
    view-z に換算して渡す値、`screen_edge_classify.cpp` の `outlineSuppress`) を
    object 方式にも渡す。fog が無効なら far clip だけで判定する。
  - 背後を調べる光線には、元の主光線の探索上限 (far clip、`transparency.hpp` で主光線に
    設定する値) をそのまま使う。
  - 透視投影では視線に沿った距離と view-z が違うので、比較は view-z で行う。
  - 輪郭自身の色には、従来どおり輪郭自身の深度で fog を掛ける。

  | 不透明な板の位置 | fog 有効 | fog 無効 |
  | --- | --- | --- |
  | 球の背後で、閾値より手前 | 輪郭が消える | 輪郭が消える |
  | 同じ slab 内で、閾値より奥 | 輪郭が残る | 輪郭が消える |
  | far clip より奥 | 輪郭が残る | 輪郭が残る |
- 抽出の段階で点ごとに光線を飛ばす案 (POV-Ray の方式) は、線の太さぶんの位置ずれと
  点の間隔に結果が左右されるので採らない。
- CueMol2/3 の通常の `edges` では、mesh の線を生成し、手前の面による遮蔽を描画時の
  トレーサーに任せる。mesh の隠線を生成前に切る `ObjectSpaceEdgeOptions::visibilityClip`、
  CLI の `--obj-edge-visibility`、専用の `edge_mesh_bvh` とそのビルド登録を削除する。
  その経路にだけある端点の alpha の受け渡しとテストも一緒に消え、頂点の alpha は
  §7 で既定の経路に入れる (CueMol は今 object 方式を使っていないので、影響は無い)。
  `silhouette` では上記の背後判定を加え、球・stick の接合部には §2.4 の内外判定を使う。
- silhouette モードでは、開いた mesh の外周 (片側にしか面が無い辺) も輪郭の候補に
  含める。screen 方式は `egtype=silhouette` で border を無効にしても背景と面の境を
  線にするが、object 方式は border を無効にすると外周の線を作らない (画面に正対した
  三角形 1 枚で線が 0 本)。POV-Ray も片側にしか面が無い辺を輪郭の候補にしていた。
  outline モードのセクションでは、mesh の抽出で外周の辺を silhouette として出し、
  上記の背後判定で背景に接する所だけを残す。
  - 線の位置: 外周の辺の上に円柱の中心を置くと、面側の半分は背後判定で面に重なって
    消え、背景側に残るのは線の半径 (`eglinew`) だけになる。線全体を背景側に
    出すため、開いた外周に限って、円柱の中心を
    外向きに線の半径 (`raise` によらない) だけずらす。向きは、画面に投影した辺に垂直で面から
    離れる向き (視線に垂直な平面内) にする。面の平面内でずらすと、傾いた面では画面上の
    移動が縮む (75 度傾けると 0.05 Å が約 0.013 Å になり、背景側の幅が足りない)。
    線の全幅 `2 * eglinew` が背景側に出る。
  - 外周の頂点では、辺ごとに別の向きへずらすので、ずらした 2 辺の端が離れる。鋭い
    凸角では先端が二股に見える (頂角 30 度で、頂点の少し先の中央が背景色。POV-Ray は
    辺の上に半径 `eglinew` の円柱を置くので先端が丸く埋まる)。外周の頂点ごとに、
    ずらした 2 辺の端を、元の頂点を中心とする線の半径の円弧 (視線に垂直な面内、
    角度に応じた数分割) でつなぎ、同じ鎖にする。線の外縁が頂点のまわりで円になり、
    先端が丸く埋まる。鎖がつながるので、半透明の線でも
    つなぎ目は濃くならない。

### 2.4 球・円柱の切り落とし: 対象の規則 (段階 1) と高速化 (段階 3) (umbreon)

- 内外判定を、球と円柱だけの Embree の BVH に対する点の問い合わせ (近傍の立体だけを
  調べる) に替える。結果は総当たりと同じ。大きな ball-and-stick (数万原子) で、
  edge の生成時間が描画時間に比べて無視できることを確かめる。
- Embree の `rtcPointQuery` は、描画に使う point 型の球・curve 型の円柱を問い合わせの
  対象にしない。切り落とし専用のシーンを別に作り、各立体の AABB を
  `RTC_GEOMETRY_TYPE_USER` の境界コールバックで返して登録する。輪郭上の点を半径 0 で
  問い合わせ、コールバックに来た候補にだけ今の内外判定と除外条件 (`insideAnySolid` の
  `srcSphere` / `srcCyl`) を当てる。木の構築と探索は Embree に任せ、
  AABB ツリーを自作しない。
- 切り落としの遮蔽物から除く立体 (総当たりの今の `insideAnySolid` にも同じ条件を
  入れ、高速化の前後で結果を揃える):
  - 別のセクションの立体 (不透明・半透明を問わない)。切り落としは同じセクションの
    球・stick の接合部のためのもので、別のセクションの立体による見え隠れは本体の
    主光線 (遮蔽・透過・slab) に任せる。今は別のセクションの外球で包んだ内球の輪郭が
    全部切り落とされ、次の 2 つで POV-Ray と違う:
    - 外球が半透明: 本体は透けて見えるのに、輪郭が消える (POV-Ray では外球越しに
      輪郭が見える)。
    - 外球が不透明で、手前のクリップ面 (slab) が外球の前面を切る: 内球が見えるのに、
      輪郭が消える (POV-Ray では輪郭が出る)。
    同じセクションの立体どうし (半透明でも) は今どおり切り落とす。
  - (除かないもの) 球より細い bond も球の輪を切る。以前は「細い bond では輪を切らず
    一周残す」(OpenGL の表示に合わせた例外) だったが、POV-Ray の画像を正解として
    比べると、bond が球から出る所で bond の 2 本の側線の間に輪の円弧が残り、POV-Ray と
    違った。例外を外すと 1CRN の ball-and-stick で POV-Ray とほぼ一致した。
- 内外判定の位置と区間の端: POV-Ray (輪郭の頂点ごとに面の上の点の見え隠れを判定し、
  片端が見える辺は丸ごと描く) に合わせる。
  - 判定は、持ち上げた線の点ではなく、持ち上げる前の面の上の点で行う (球の輪は球の
    中心、端面の縁は端面の中心を基準に縮め、円柱の側線は軸から半径の位置に戻す)。
    持ち上げた点で判定すると、同じ半径の stick (licorice) では輪が bond の外に出て
    切られず、stick の内側に輪の円弧が残った。
  - 残す区間の端は二分法で面との交点まで詰め、直線はさらに線の半径だけ延ばす
    (はみ出した分は本体の遮蔽が隠す)。延ばさないと、球の輪と stick の側線の間に隙間が
    出た。円弧 (Bézier) は延ばさず、端に丸いふた (ごく短い直線の円柱) を付ける。
    Bézier の管は端が平らなので、切れた円弧が別の線と角度を持って出会う所 (stick の
    折れ目の外側) に隙間ができた。延ばすと、ふたが stick の手前に出て余分な点になった。
- view clip と edge 線: 線 (管) は中心線の深さで判定する。中心線が [clipNear,
  clipFar] の内なら太さ全体を描き、外なら全体を消す (`intersectPrimary`)。管そのものを
  clip 面で切ると、near clip のすぐ奥の球の輪などが欠けたり細長い切れ端になったりした。
  fog と far clip の効き方は screen 方式と揃っていることを確かめた (1ehz、edges /
  silhouette)。screen 方式は、線の手前の深さが clip 面から (far - near) の 2% 以内の
  輪郭を切り口とみなして描かない (867567c) ので、near clip のすぐ奥にある切られて
  いない物体の輪郭も消える。object 方式は形から輪郭を計算し、切り口の縁には線を
  作らないので、この判定は持たない (実際の形どおり描く)。
- 切り口の内側の線: near clip で開いた物体の内側 (切った分子表面の奥の壁、切った
  リボンの内側) に見える線は描かない。screen 方式の決まり (最初の面が裏面で、near clip
  が手前の面を消している画素に接する輪郭は描かない) に合わせる。線の中心から横へ半径の
  半分ずらした 2 本の視線のどちらかが、その切り口を見ていたら、線全体を消す
  (`edgeNextToCut`)。画素ごとに判定すると、面に重なる側の半分だけが残った (切り口から
  見える空洞の泡の輪郭)。横のずれを半径の 2 倍にすると、clip がかすめる bond の側線や、
  奥で開いた球の輪が欠けた (screen 方式は線の隣の画素しか見ない)。線の中心から光線を
  出す判定にすると、持ち上げで線が壁から浮くため、奥の壁の折れ目の線が残った。
  dsurface (meshms) と DefaultRibbon で screen 方式と比べ、screen にしか無い線は
  増やさずに、object にしか無い線を減らした (分子表面で 47546 px → 7702 px)。残りは
  上の 2% 帯の輪郭。
- near clip のある場面は POV-Ray を正解にできない。POV-Ray の輪郭計算と見え隠れの判定
  (`RendIntData::calcSilEdgeLines` / `buildAABBTree`) は near clip で切る前の mesh を
  使い、切った mesh (`calcMeshClip`) は面の書き出しにしか使わないので、near clip で
  消えた手前の面の奥の線が途切れたり消えたりする (1ehz で確認)。umbreon は主光線の
  始点を near clip まで進めるだけなので、この問題は無い。clip なしの比較 (1ehz、球・
  bond の太さと拡大率を変えた 6 通り) では POV-Ray とほぼ一致した。
  - 1CRN の全原子 ball-and-stick (球 0.3 / bond 0.2) と stick (0.2 / 0.2) を 4 方向
    から描き、POV-Ray (`detail` 30) と比べて、どちらも余分な線・欠けた線がほぼ 0 に
    なることを確かめた。POV-Ray の分割は renderer の `detail` で決まり、既定の 3 では
    球の輪郭が 8 角形になるので、比べるときは `detail` を上げる。
  - 線描画由来の円柱 (§2.2 の印。同じセクションでも除く)。

### 2.5 線のつなぎ目 (umbreon)

- 形状は先に足さない。`ROUND_LINEAR_CURVE` は鎖の内側の継ぎ目を 1 つの球の掃引にし、
  両端に丸い端を持つ (§1.1)。POV-Ray は開いた線分の継ぎ目に線幅と同じ半径の球を
  置き、半透明の線では重なりの濃淡を避けるため省いていた。umbreon は今の形でこれに
  相当する。
- 確認は 2 つに分ける:
  - stick の joint・末端 (stick と同じ半径の球がある): 斜めから見て、円柱の側線と球の
    輪郭がつながること。
  - 輪郭線自体の継ぎ目 (別々の鎖が出会う所、輪郭と境界など): 不透明の線では継ぎ目が
    閉じること。半透明の線の継ぎ目の濃さは §7 で扱う。
- 隙間が再現した箇所に限って形状を補う。

### 2.6 影・AO・GI (umbreon)

- object-space の輪郭線は、指定された線色をそのまま合成に渡す。直接光・影・環境光・AO・GI は
  線の RGB に作用しない。半透明や AA による被覆、fog は通常どおり合成する。
- edge の円柱は影を落とさず、AO・GI の遮蔽物にもならないようにする。

### 2.7 veil (セクション単位の半透明) (umbreon)

- group alpha (veil): 円柱はセクションの group を持つので、veil のパスでは veil と
  一緒に現れ、背景のパスでは隠れる。円柱は実際の物体なので、per-pixel の合成でも深度の
  判定 (`veilCovers`) で veil として扱われ、veil の外側に出た線も残るはず (stroke で
  必要だったインクの被覆の記録は要らない)。これをテストで固定する。
- 別のセクションの立体の内側の輪郭: §2.4 の規則で、veil の球で包んだ内球の輪郭も
  切り落とさない。veil のパスでは veil 越しに、背景のパスではそのまま線が見え、
  合成で veil の alpha に従って混ざる。
- 色の alpha・頂点の alpha による線の薄れと、半透明な線の奥の veil は §7 (別タスク) で
  扱う。

### 2.8 そのまま使えるもの

- fog: 深度による後処理なので、円柱にも掛かる。確認だけ行う (silhouette モードの
  輪郭を消す範囲は §2.3)。
- クリップ面 (slab): 主光線の範囲の制限で、円柱も一緒に切られる。断面に沿った線は
  出ない (GL も出ない)。今回は扱わない。

扱わないもの: 完全に透明な面の後ろの物体に掛かる fog。fog の後処理は最前面の深度
(`transparency.hpp` の最初の当たり) を使うので、alpha 0 の面の後ろの物体に、その面の
深度で fog が掛かる。edge を無効にしても起きる共通の fog 処理の問題で、線の alpha の
補間とは独立なので、別の作業にする。

扱わないもの: 面ごとの境界線・折れ目の抑制指定 (密度マップなどが、面の境界の点状の
ノイズを避けるために持つ指定)。POV-Ray writer は参照するが、umbreon exporter は mesh に
引き継いでいない。今後の検討事項にする。

扱わないもの: 半透明な線の奥の面の間接光 (GI)。pt2 の GI の対象は最初の当たり
(`transparency.hpp` の `firstGiEligible` など) で決まるので、alpha 0 の線の奥の板の
間接光が落ちる。線に限らず半透明な面全般で起きるレンダリングエンジン本体の問題で、
edge の側では扱わない (必要なら本体の別の作業にする)。

扱わないもの: 原子間相互作用の `flat` 末端など、球を置かない円柱の端の外周に線が
出ないこと。CueMol の POV-Ray writer の経路でも同じく側線 2 本だけで、umbreon と
一致する。端面を明示的に作る `cylinderCap()` の外周の線も、今回は比べない。

## 3. 進め方

3 つの段階に分け、段階ごとに umbreon の PR → cuemol2 で `UMBREON_GIT_REF` を移す PR を
出してマージする (PR を積まない)。頂点・色の alpha による半透明の線は、どの段階にも
入れない (§7)。

### 段階 1: 不透明なシーンで完成させる

対象: §2.0 (移動)、§2.1 (切り替え・太さ・`raise`・`camBias` の上限・Bézier の輪)、
§2.2 (セクションごとの表・セクション内の隣接判定・線描画由来の円柱)、§2.3
(silhouette モード、開いた外周を含む)、§2.4 の切り落とし対象の規則 (総当たりのまま)、
§2.5 の stick の確認、§2.6、`visibilityClip` の削除。

1. umbreon: §2.0 のディレクトリの移動だけを 1 コミットで行い、`task` のテストが
   全部通ることを確かめる。
2. umbreon: §2.2 と §2.6。CLI にセクションごとの指定 (`--obj-edge ID=spec`、`--edge` と
   同じ形) を足し、umbreon_cli で確かめられるようにする。
3. umbreon: §2.1 の `raise` の定義の統一・`camBias` の上限・Bézier の輪、§2.3 (§2.0 の
   判定の共通化を含む)、§2.4 の切り落とし対象の規則、`visibilityClip` の削除。
4. cuemol2: §2.1 (切り替えと対応付け、GUI なし)。`install_umbreon` した手元のビルドで、
   console / スクリプトから screen 方式・object 方式の画像を同じシーン・カメラで
   書き出し、GL の表示と並べて、ユーザーに目視で確認してもらう。持ち上げ (線の内縁が
   面の外周に接するか、球と mesh の両方)、stick の継ぎ目 (§2.5)、`camBias` の上限で
   輪郭が途切れないかはここで確かめる。確認するシーン (すべて不透明):
   - 分子表面 + ribbon + ball-and-stick (edges モード、silhouette モード)
   - fog あり、透視投影
   - renderer ごとの設定の受け渡し: 画面に見えている 2 つの renderer に違う `egcolor`
     と `eglinew` を指定し、object 方式の画像で見分けられること。続けて片方だけを
     `egtype=none` にし、その renderer の輪郭だけが消えること (§4 の単体テストは
     umbreon のスタイル表を直接設定するので、cuemol2 からの受け渡しはここで見る)。
5. 確定後に段階 1 のテスト (§4) を足し、PR を出す。

### 段階 2: veil (セクション単位の半透明)

対象: §2.7。

1. umbreon: veil の外側に出た線が残ることと、veil で包んだ内側の輪郭が見えることを
   確かめる (§2.7)。直す所が出たらここで直す。
2. cuemol2: 目視で確認してもらう。確認するシーン:
   - 半透明の分子表面 (alpha 0.6、per-pixel) + 中の stick (`~/Desktop/veil.qsc` など)
   - 同じシーンを silhouette モードで
3. 段階 2 のテストを足し、PR を出す。

結果: 直す所は無かった。group alpha の合成はパスごとに `renderFrameRaw` を呼び、edge の
線はそのたびに隠すセクションを除いた場面から作り直す (`PassRunner::run`)。背景のパスに
veil のセクションの線 (円柱・円弧とも) は無く、veil のパスでは veil と一緒に現れる。
`~/Desktop/veil.qsc` (分子表面 alpha 0.6、per-pixel、中の stick にも線) を edges /
silhouette の両モードで screen 方式と比べ、目視でも確認した。

### 段階 3: 切り落としの高速化

対象: §2.4 の BVH。大きな構造 (数万原子の ball-and-stick) で edge の生成時間を測り、
総当たりと結果が同じことを確かめる。既存の切り落としのテストがそのまま通ることで
検証する (新しいテストは足さない)。

結果: 切り落としの判定を `ClipSolids` (`object_space_edges.cpp`) にまとめた。対象の
球・円柱の AABB (`kClipEps` より広く取る) を、切り落とし専用の Embree シーンの user
geometry に登録し、輪郭上の点を半径 0 で問い合わせ (`rtcPointQuery`)、AABB が点を含む
立体にだけ今の内外判定を当てる。さらに、輪郭ごとの切り落としを TBB で並列にした
(256 本ずつの塊の結果を順につなぐので、出力の順は逐次と同じ)。格子状の
ball-and-stick (球 0.3 / bond 0.2、線の半径 0.05) で測った:

| 原子 / bond | 総当たり | BVH (逐次) | BVH + 並列 |
|---|---|---|---|
| 3,200 / 4,160 | 8.4 s | 0.21 s | 0.05 s |
| 32,000 / 41,600 | (約 800 s の見込み) | 1.6 s | 0.43 s |

出力 (線の端点と円弧の制御点) は総当たりとバイト単位で一致した。32,000 原子の場面を
1200x1200 で描くと、AO も supersample も無い既定の設定で線なし 0.11 s、線あり 0.69 s
(CueMol の通常の設定では描画が数秒かかるので、生成時間の割合はさらに小さい)。

### そのあと

目視の結果を見て、CueMol の既定の方式を object にするかを決める (§6)。

## 4. テスト

umbreon (`tests/test_object_space_edges.cpp`)。球・stick の接合部は既存の回帰テストで
確かめる (球に入り込む stick の側線が切れ、stick と接する球の輪郭は、細い stick でも
同じ半径の stick でも接合部で切れること)。既存のテスト (7) は輪郭を
数え分けるため球を `group=1`、stick を `group=2` に置いているので、§2.4 の「同じ
セクションだけで切る」規則では、同じ半径の stick が球の輪を切る判定が通らなくなる。
球と stick を同じセクションに置き直し、球単独の輪を基準に、細い stick でも同じ半径の
stick でも接合側の円弧だけが切れることを確かめる形に直す (輪の描き方によらず使える
期待値)。

### 段階 1

- セクションごとの表: 2 つのセクションに違う色・半径を指定し、それぞれの輪郭の円柱が
  その色・半径になること。無効のセクションには円柱ができないこと。線描画由来の円柱
  (§2.2) には、輪郭が有効なセクションでも円柱ができないこと。
- セクション境界: renderer A の三角形の 1 辺に、線を無効にした renderer B の三角形を
  同一平面上で接続する。A の境界線が、B を置く前と同じ 3 辺になること。
- silhouette モード: 板の手前に球を置き、背景の前の輪郭は描かれ、板の前の輪郭は
  描かれない (板の色のまま) こと。続けて、球・カメラ・far clip を固定し、板に重なる
  同じ輪郭の画素で、fog の閾値と far clip の効果を 1 つずつ変えて確かめる (同じ
  テストの中で順に判定する):

  | 操作 | 期待する結果 |
  | --- | --- |
  | fog を有効にし、板の view-z を `outlineFarVz` より手前に置く | 輪郭が消える |
  | fog は有効のまま、板だけを閾値より奥、far clip より手前に移す | 輪郭が現れる |
  | 板を固定し、fog だけを無効にする | 輪郭が消える |
  | fog は無効のまま、板だけを far clip より奥に移す | 輪郭が現れる |
- silhouette モードの開いた mesh: border を無効にした三角形 1 枚の、半分だけに背後の
  不透明な板が重なるシーンで、背景に接する外周には線が出て、板に重なる区間では
  消えること。`eglinew = 0.05 Å` で、辺から背景側へ 0.075 Å の画素にも線が出ること。
  三角形を外周の 1 辺を軸に正対から 75 度傾けても同じ画素に線が出ること。頂角 30 度の
  頂点で、二等分線上の先端のすぐ外側 (頂点から約 0.053 Å) も線の色になること。
- 切り落とし対象の規則: 不透明な球を別のセクションの不透明な球で包み、手前の slab が
  外球の前面を切ると内球の輪郭の画素に線が出て、前面が残ると線が隠れること。同じ
  セクションの stick の少し奥にワイヤー (線描画由来の円柱) を置いても、stick の側線が
  切られないこと。
- 持ち上げ: 正射影で、視線と単位法線が直交する輪郭点を選ぶ。元の輪郭点から生成した
  線の中心の端点への変位と、単位法線との内積が、球・mesh ともに指定した `raise` と
  一致すること。細い線 (半径 5 Å の球、線幅 0.01 Å) の球の輪で、中心線を一周する
  光線がすべて線に当たること (Bézier の輪が途切れないこと)。
- 板に覆われた輪郭: 通常の edges モードで、薄い閉じた mesh を不透明な板で完全に
  覆うと、輪郭線も板に隠れる (板の色のまま) こと。
- 照明に左右されない線: 環境光を灰色 (0.4, 0.4, 0.4) にし、fog を切る。AO・GI の
  オン・オフで、不透明な線が全面を覆う画素のリニア RGB が指定した線色と一致すること。
  同じシーンで、edge の円柱が板に影を落とさないこと。

### 段階 2

- veil: alpha 0.6 の veil の輪郭の外側の画素が、per-pixel の合成で背景と線の色を
  0.4 : 0.6 で混ぜた色になること。同じテストで、不透明な球を veil の球で包み、内球の
  輪郭の画素に線が (veil 越しに) 出ること。

cuemol2: 対応付けは目視で確定するので、テストは足さない。

## 5. 決めたこと

- 線の太さ: `eglinew` (Å、ワールド空間の実際の長さ) を円柱の半径とする。POV-Ray の
  出力と揃える (§2.1)。
- 折れ目 (crease): GL には無い。CueMol の今の stroke の対応付け (crease の角度が
  0 より大きいときだけ) に揃える。
- 方式の切り替えは console / スクリプトからだけにし、GUI は後続にする (§2.1)。
- スタイル表の添字はセクション ID (§2.2)。
- `raise` は線の中心の変位の、輪郭の法線方向の成分 (§2.1)。
- 球・円柱の輪は円形断面の 3 次 Bézier 曲線 (1 周 8 本) で描く。折れ線の分割数の
  調整・外接は採らない (§2.1)。
- mesh の輪郭の視点方向の補正 (`camBias`) には、線の半径に応じた上限を設ける (§2.1)。
- silhouette モードでは、開いた mesh の外周も輪郭の候補にし、線の中心を面の外向きに
  線の半径だけずらす (§2.3)。
- 球・円柱の輪郭の切り落としは同じセクションの立体だけで行い、別のセクションの立体に
  よる見え隠れは本体の主光線に任せる (§2.4)。
- 線描画 (`startLines()`) 由来の円柱からは輪郭を作らない (§2.2)。
- 頂点・色の alpha による半透明の線は、この plan の段階に入れず、問題を明確にした
  うえで別のタスクにする (§7)。veil は段階 2 で扱う。
- 線の遮蔽と alpha の合成はレンダリングエンジン本体に任せ、edge の側で同じ計算を
  しない。
- 既存の POV-Ray writer → POV-Ray の経路でも同じく起きる問題は、今回は直さない。
- silhouette モードで、不透明な物体の輪郭の背後に半透明の veil があるとき、手前の
  輪郭線はそのまま残る挙動を許容する (§2.3・§2.7)。veil 自身の外周線が背景と veil の
  alpha で合成されることは §4 のテストで確かめる。

## 6. 決めること

- 既定の方式: 当面は screen のまま。段階 2 のあと (§3 の「そのあと」)、目視の結果から
  object にするかを決める。

## 7. 別タスク: 頂点・色の alpha による半透明の線

頂点の alpha (tube の末端のフェードなど) や色の alpha による半透明は、使われる場面は
あるが頻度は高くない。この plan の段階には入れず、問題を明確にしたうえで別のタスク
(別の plan) にする。レビューで見つかった、umbreon でだけ起きる (POV-Ray では起きない)
問題を、そのときの出発点として残す。

- 線の端点の alpha:
  - 滑らかな輪郭が三角形の辺を横切る点 (合成した点) は alpha を持たず不透明のまま。
    辺の両端の頂点の alpha を補間して付ける。
  - 既定の経路は円柱にするときに端点の alpha を渡さない (`makeEdge(s.p0, s.p1, opt,
    s.group)`)。両端の alpha を渡す。片端の alpha が 0 の線分も捨てず、途中の半透明の
    部分は描く。目標は screen 方式 (`surfAlpha` を線の不透明度に掛ける) と同じ「面と
    線が一緒に薄れる」見え方。線の濃さは、円柱の手前と奥の両面で透過率が掛かる今の
    描画 (POV-Ray と同じ) を許容する。
  - 球・円柱の輪郭にも、元の立体の色の alpha を載せる。
- 半透明の線でだけ見える濃い点:
  - 連結の向き: 今の連結 (`curve_build.cpp`) は一方の終点と他方の始点が会う場合だけを
    つなぐので、始点どうし・終点どうしが会う所で丸い端が重なる (alpha 0.5 の直線の
    外周で、線の途中 0.25、継ぎ目 0.0625)。2 本だけが会う頂点では、円柱にする前
    (`FeatureSeg` の端点と `alpha0` / `alpha1`) で一方を反転してから連結する (円柱の
    `(color.w, opacity1) = (1, -1)` を単純に入れ替えると不透明な線が抜ける)。
  - 閉じた輪: 最後と最初の線分もつなぎ、Embree の隣接区間に指定する (今は輪の始点で
    丸い端が重なる)。
  - 輪郭と折れ目の重複: 同じセクションの同じ mesh の辺が輪郭と折れ目の両方に当たると
    円柱が 2 本できる。溶接した頂点の組で重複を除く。
- 完全に透明な立体・面:
  - 色の alpha が 0 の立体を、球・円柱の切り落としの遮蔽物から除く (同じセクションの
    alpha 0 の球で包んだ内球の輪郭が消える)。
  - silhouette モードの背後判定で、alpha 0 の面に当たったらその先まで調べる。
- 半透明な線の奥の veil: 不透明なセクションの線が薄れていて奥に veil があると、背景の
  パスと veil のパスで最初の当たりが同じ線になり、`veilCovers` が veil の色を外す。
  線に限らず、色の alpha が 1 未満の面の奥の veil でも起きる。遮蔽と透過は本体が
  計算しているので、本体の透過処理で表示中の veil のセクションが色に寄与したかを
  記録し、`blendPerPixel()` の被覆の判定をその記録に替える案がある。寄与を「有無」で
  記録すると、veil 2 枚の間のほぼ不透明な線で、本体の透過の打ち切り (`kOpaque`) の
  所で重みが段差で変わる (この制限を許すかもそのタスクで決める)。
- 関連して、本体側の別の問題 (§2.8 の「扱わないもの」): alpha 0 の面の後ろに掛かる
  fog、半透明な線の奥の面の GI。
