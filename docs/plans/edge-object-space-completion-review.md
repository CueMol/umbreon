# CueMol の object-space edge 対応計画へのレビュー

## 1. 半透明の線は本体と一緒に薄くし、濃さは POV-Ray の挙動を許容する

tube の末端では、mesh の頂点 alpha を輪郭上でも補間し、生成する円柱の両端に渡す。片端の alpha が 0 でも途中の半透明部分は描き、完全透明の部分では線自体の寄与を 0 にする。screen-space 側にはすでに本体の透明度に線が追従する実装とテストがある。[計画 §2.7](edge-object-space-completion.md#L226)・[screen-space の描画テスト](../../tests/test_screen_vector_edges.cpp#L1632)

**円柱単体の濃さは現状を許容する。** 白地に不透明度 0.5 の黒い円柱を置くと、手前と奥の側面を通るため、背景の寄与は 0.5 × 0.5 = 0.25 になる。Umbreon と CueMol の `edge_line2` を使った POV-Ray の実測は一致した。screen-space の線との画素値の差について、補正は不要とする。[半透明の線を出力した実シーン](../../data/1ab0_scene5_transp2.inc#L28483)

**継ぎ目は同じ配置の POV-Ray 出力と比べる。** CueMol の writer は `union` を使い、半透明の頂点では継ぎ目の球を省いている。比較用に球を重ねた試験では、白を 255 とすると円柱単体が 64、球を重ねた箇所が `union` で 16、`merge` で 64 だった。継ぎ目だけに濃い点が出る場合は、Umbreon 固有の差が再現した箇所を修正対象とする。[計画 §2.5](edge-object-space-completion.md#L216)

**§2.5 の半透明の継ぎ目は、一直線の外周で再現した。** 2枚の三角形で直線の外周を作り、頂点 alpha を一様に 0.5 にした。計画どおり端点 alpha を渡して白地に黒線を描くと、Umbreon での明るさ（リニア値）は線の途中で 0.25、共有頂点の近くで 0.0625 になった。同じ mesh を CueMol の writer から POV-Ray で描くと、どちらの画素も RGB (136, 136, 136) だった。現在の連結処理は一方の終点と他方の始点が会う場合だけをつなぐため、始点どうしが会うと丸い端が重なる。連結可能な2本だけが会う頂点では端点の向きを揃え、反転する線分は両端の alpha も入れ替えたい。回帰テストでは継ぎ目とその両側が同じ濃さになることを確認する。[計画 §2.5](edge-object-space-completion.md#L266)・[円柱の連結条件](../../src/umbreon/render/curve_build.cpp#L116)

**§2.5 で線分を反転するときは、両端の実際の alpha を交換する。** `makeEdge()` は両端が不透明な線を `(color.w, opacity1) = (1, -1)` として格納する。`-1` は全区間で始点と同じ不透明度を使う指定である。格納済みの2値を単純交換する試験では、白地の黒線が途中で白く抜けた。同じ mesh の CueMol → POV-Ray 出力では線全体が黒だった。`makeEdge()` に渡す前に両端の alpha を交換するか、円柱の段階で反転するなら `opacity1 < 0` のときは両方の値を保持したい。§4 の連結テストでは、不透明な線が黒のまま保たれることと、片端だけ透明な線を反転してもフェードの向きが画面上で変わらないことを確認する。[計画 §2.5](edge-object-space-completion.md#L282)・[端点 alpha の格納](../../src/umbreon/edges/object_space_edges.cpp#L52)・[計画 §4 の連結テスト](edge-object-space-completion.md#L410)

**§2.3・§2.5 の閉じた輪郭では、最後の線分と最初の線分もつなぐ。** 全線分の向きを揃えた alpha 0.5 の黒い外周で、直線部分に輪の始点を置くと、その近くの明るさ（リニア値）は 0.0625、線の途中は 0.25 だった。線分の並び順だけを変えて始点を別の場所に移すと、同じ画素は 0.25 に戻った。同じ mesh の CueMol → POV-Ray 出力ではどちらの位置も RGB (136, 136, 136) だった。閉じた輪の前後の制御点を補い、末尾と先頭を Embree の隣接区間に指定した試験では、始点の位置によらず 0.25 で揃った。§4 では同じ半透明の輪郭の始点を移しても継ぎ目の濃さが変わらないことを確認したい。[計画 §2.3 の外周円弧](edge-object-space-completion.md#L234)・[曲線の隣接フラグ](../../src/umbreon/render/curve_build.cpp#L148)

**§2.2 では、同じセクションの同じ mesh 辺が輪郭と折れ目の両方に該当するとき、円柱を1本だけ生成する。** 直角に折った2枚の三角形を、共有辺が外形に見える向きに置いた。現行の抽出器は、折れ目を有効にすると共有辺を輪郭と折れ目として1本ずつ返す。計画の持ち上げ量と頂点 alpha 0.5 を適用して白地に黒線を描くと、辺の中央の明るさ（リニア値）は折れ目が無効なら 0.25、有効なら 0.0625 になった。二重に濃くなる区間は辺の全長に及ぶ。CueMol の POV-Ray writer はどちらの設定でも共有辺に円柱を1本だけ出し、POV-Ray の中央画素も同色だった。§4 ではこの共有辺について、折れ目を有効にしても円柱が1本で、線の濃さが変わらないことを確認したい。[計画 §2.2](edge-object-space-completion.md#L169)・[輪郭と折れ目の抽出](../../src/umbreon/edges/mesh_feature_edges.cpp#L711)

**頂点 alpha で薄れる線を通して、背後の半透明な板の色が見えることを確認する。** 通常の `edges` モードで、黒い輪郭の後ろにセクション alpha 0.6 の緑の板を置き、手前の mesh の外側で線だけを通る画素を調べた。CueMol の writer 出力を POV-Ray で描いて `blendpng` で合成すると、線の alpha が 0 の画素は線を無効にしたときと同じ薄緑、0.5 の画素は暗い緑になった。現行の Umbreon に計画どおりの端点 alpha を渡すと、per-pixel 合成の結果はそれぞれ白と灰色になった。板を表示したパスと隠したパスで最初のヒットが同じ輪郭線になり、深度が等しいため、`veilCovers` が板の色を合成から外す。§2.7 の合成判定には、線を透過した先で見えるセクションの寄与も含めたい。§4 では線の alpha を 0 と 0.5 に切り替え、両方で板の緑が残ることを確認する。[計画 §2.7](edge-object-space-completion.md#L264)・[最初のヒットの深度記録](../../src/umbreon/shading/transparency.hpp#L408)・[per-pixel の合成判定](../../src/umbreon/blend/group_blend.cpp#L345)

**輪郭線は GI の受光・遮蔽から除外し、線越しに見える面の間接光を残す。** 不透明な緑の板の手前に alpha 0 の黒線を置いた。Umbreon の `pt2` で間接光を主な光源にすると、線なしで 0.663 だった画素の緑成分（リニア RGB）が 0 になった。最初に当たった線で GI の対象が決まり、背後の板の間接光まで落ちるためである。CueMol の writer 出力を POV-Ray の radiosity 有効で描くと、線なしと alpha 0 は同じ画素値だった。§2.6 では線を指定色で合成し、§2.7 では板の間接光にも線の透過率を適用したい。tube 末端の完全透明部分は線なしと同色になり、フェード途中でも背後の面の明るさが連続することを確認する。[計画 §2.6](edge-object-space-completion.md#L260)・[GI の対象を記録する処理](../../src/umbreon/shading/transparency.hpp#L428)・[間接光の合成](../../src/umbreon/render/embree_renderer.cpp#L968)

**§2.7 では、本体の透過処理が求めた奥の板の寄与量を合成に渡し、線のフェードを連続させる。** §4 の配置どおり、手前から赤い板（セクション alpha 0.4）、黒線、緑の板（同 0.6）を置いた。不透明な黒線では、CueMol の POV-Ray writer の出力を POV-Ray と `blendpng` で描画すると、緑の板の有無にかかわらず線上は RGB (102, 14, 14) になる。計画の「奥の板が少しでも寄与したか」という判定で、この不透明時の挙動は再現できる。[計画 §2.7](edge-object-space-completion.md#L276)

一方、黒線の alpha を 0.98 から 0.99 に上げると、Umbreon で描画した各パスに計画の判定と現行の合成式を適用した場合、線上の赤成分は 78 から 102 に跳ぶ（255段階）。奥の緑はすでにほぼ見えないが、本体が透過を打ち切ったところで奥の板が合成から外れ、手前の赤い板の重みまで変わる。POV-Ray と `blendpng` で実測した赤成分はどちらも 102 だった。奥の板の寄与がゼロに近づくにつれて合成の重みも連続して変わるようにし、§4 の既存テストに alpha 0.98 と 0.99 を加えて、この段差を検出したい。遮蔽と透過率の計算は本体に任せる。[本体が計算する寄与と打ち切り](../../src/umbreon/shading/transparency.hpp#L456)・[複数セクションの重み付け](../../src/umbreon/blend/group_blend.cpp#L354)・[計画 §4 のテスト](edge-object-space-completion.md#L379)

## 2. 球はプリミティブのまま保ち、細い輪郭を円弧に沿わせる

現行の48分割では円周上の点を直線で結ぶため、端点の持ち上げ量が正しくても、線分の中央は球に埋まり得る。正射影で半径 5 Å の球に幅 0.01 Å の黒線を描いたところ、分割点では黒く、隣の分割点との中間では白い背景が見えた。同じ位置は192分割で黒くなった。確認条件には、端点に加えて分割点間でも線が連続することを含めたい。[輪郭の生成](../../src/umbreon/edges/analytic_silhouette.cpp#L30)・[計画 §2.1](edge-object-space-completion.md#L122)

POV-Ray writer は edge を描く球を mesh 化し、その表面から輪郭を抽出していた。Umbreon は正射影・透視投影ともに球の輪郭円を計算できるので、球本体は解析プリミティブとして描き、輪郭だけを曲線にする案がある。Embree 4.4.1 の円形断面の3次 Bézier 曲線で円弧を近似した単体試験では、上記の球に45度ずつ8本の曲線を置くと、中心線を一周する3,600本の光線すべてが線に当たった。これは単独の球で確認した実装候補であり、stick に埋まる区間を切った後も残りが円弧に沿うことは、組み込み時に確認する。[接合部の切り落とし](../../src/umbreon/edges/object_space_edges.cpp#L140)

**計画で採用した外接多角形では、分割点で球と線の間に背景が見える。** 同じ球と線幅で48分割の `circumscribe` を有効にすると、球面から線の中心までの距離は弦の中央で 0.00499 Å、分割点で 0.01573 Å だった。線半径は 0.005 Å なので、分割点付近では球と線の内縁が線幅約1本分離れる。実際にその間の画素は白い背景色になった。折れ線を使う場合は、球の半径と指定線幅に応じて分割数を選びたい。§4 のテストでは、分割点と弦の中央の両方で、中心の持ち上げ量と `raise` の差が線幅に対して十分小さいことを確かめる。これで線の埋まりと浮きの両方を検出できる。[外接輪の生成](../../src/umbreon/edges/analytic_silhouette.cpp#L58)・[計画 §2.1](edge-object-space-completion.md#L136)・[計画 §4 のテスト条件](edge-object-space-completion.md#L318)

**折れ線で描く輪では、分割数の未指定と明示値を区別する。** 最新の §2.1 は球の輪と円柱の端面を折れ線で描き、未指定時は線幅に応じて分割数を選ぶ方針である。現在の API と CLI はともに既定値が 48 で、CLI は省略時にも 48 を渡す。たとえば未指定を 0 で表せば、細い輪郭では自動で分割数を増やし、16～32 分割を明示する既存テストの期待値も維持できる。球に上記の Bézier 曲線案を採用する場合、この分割数の指摘は折れ線を使う輪に限る。球については、stick との接合部を切った後も残った線が円弧に沿うことを確認したい。[計画 §2.1](edge-object-space-completion.md#L149)・[計画 §5](edge-object-space-completion.md#L464)・[API の既定値](../../src/umbreon/render/edge_types.hpp#L326)・[CLI からの受け渡し](../../src/bench/scene_setup.cpp#L895)

## 3. 面ごとの境界線・折れ目の抑制指定は保留する

CueMol の密度マップなどは、面の境界に点状のノイズが出るのを避けるため、面ごとに線を抑制する指定を持つ。POV-Ray writer はこの指定を参照するが、現行の Umbreon exporter は mesh に引き継いでいない。この対応は今後の検討事項とする。

## 4. 削除対象を mesh の事前隠線処理に限定する

`visibilityClip` は、輪郭からカメラまでの間に mesh がある区間を、線の生成前に切り落とす Umbreon のオプションで、既定はオフ。完全透明な三角形を不透明な三角形の手前に置いた試験では、奥に生成される境界線はオフで3本、オンで0本だった。[現行の隠線判定](../../src/umbreon/edges/edge_mesh_bvh.cpp#L105)

元の POV-Ray writer にもモードごとの隠線処理はある。通常の `edges` では一般の mesh の線を出力して手前の遮蔽を描画に任せ、球由来の線には専用処理を行う。`silhouette` では同じ renderer 内で輪郭点の奥まで調べ、外周に線を残す。Umbreon でも通常の mesh の遮蔽はトレーサーで扱える。利用者は CueMol2/3 に限られるため、このオプションの互換性維持は不要とする。

- **削除する処理**は `ObjectSpaceEdgeOptions::visibilityClip`、CLI の `--obj-edge-visibility`、専用の `edge_mesh_bvh` とそのビルド登録。頂点 alpha の受け渡しとそのテストは通常の線生成に移す。[計画の削除範囲](edge-object-space-completion.md#L186)
- **球と stick の接合部の回帰テストは、両方を同じセクションに置く。** §2.4 では同じセクション内で `ObjectSpaceEdgeOptions::clip` による内外判定を行う。既存テストは生成元を数え分けるため、球を `group=1`、stick を `group=2` にしている。切り落としに同一セクションの条件だけを加えた試験では、47チェック中「同じ半径の stick が球の輪郭を切る」の1件が失敗した。§4 の接合部テストでは球単独の輪郭を基準に、細い stick では一周残り、同じ半径では接合側の円弧が切れることを確認したい。別セクションからの遮蔽は slab の画像テストで確認できる。[計画 §2.4](edge-object-space-completion.md#L247)・[計画 §4](edge-object-space-completion.md#L375)・[既存テストの配置と期待値](../../tests/test_object_space_edges.cpp#L369)
- **§2.3 の silhouette 判定**は引き続き実装する。輪郭の背後にある物体が far clip 内かつ fog の閾値以内なら線を消す。完全透明な面に当たったら、その先の物体または背景まで調べる。球と背後の板を使い、fog と far clip を個別に変えて確認する。[計画 §2.3](edge-object-space-completion.md#L157)・[球と板のテスト条件](edge-object-space-completion.md#L286)

## 5. silhouette モードでは開いた mesh の外周も輪郭の候補に含める

CueMol の screen 方式は `egtype=silhouette` で `border` を無効にしても、背景と面の境を silhouette として検出する。同じ設定を object 方式の抽出器に渡すと、画面に正対した三角形1枚から得られる線は0本で、`border` を有効にすると3本になる。元の POV-Ray writer も通常の mesh では片側にしか面がない辺を輪郭の候補にしている。§2.2 で開いた境界も候補に含め、§2.3 で背後を判定したい。三角形の半分だけに背後の不透明な板が重なるシーンで、背景に接する外周には線が出て、板に重なる区間では消えることを確認する。[計画 §2.2](edge-object-space-completion.md#L156)・[計画 §2.3](edge-object-space-completion.md#L169)・[screen の背景境界判定](../../src/umbreon/edges/screen_edge_classify.cpp#L335)・[object の境界抽出](../../src/umbreon/edges/mesh_feature_edges.cpp#L639)

**背景側に残る線幅は、同じ `eglinew` で POV-Ray 出力と比べる。** 画面に正対した三角形の直線辺を `silhouette`、`eglinew = 0.10 Å` で出力した。POV-Ray writer は辺を中心に半径 0.10 Å の円柱を置く。正射影、1画素 0.005 Å、AA オフで、黒線は面側20画素、背景側20画素だった。円柱半径を計画と同じ 0.05 Å に揃えた対照では各10画素になった。線が元の辺に乗る配置は従来経路と共通する。一方、同じ `eglinew` で現行の Umbreon の境界線が背景側を覆うのは 0.05 Å で、計画 §2.3 の背後判定が入れば面側の半分も消える見込み。§4 では背景側 0.075 Å の画素にも線が出ることを確認したい。計画の線半径を維持するなら、開いた外周に限って中心を投影した辺の外向きへ半径分ずらす方法がある。[計画の線幅](edge-object-space-completion.md#L118)・[境界線の配置](../../src/umbreon/edges/mesh_feature_edges.cpp#L423)・[三角形と板のテスト条件](edge-object-space-completion.md#L326)

**傾いた面でも背景側の線幅を保つ。** 上記と同じ線幅・正射影で、外周の1辺を軸に三角形を正対状態から75度傾けた。計画 §2.3 の「面の平面内で辺に垂直」な方向へ中心を 0.05 Å ずらすと、画面上の移動量は約 0.013 Å に縮み、線半径を含めても背景側の幅は約 0.063 Å になる。この位置に円柱を置いて Umbreon で描くと、辺から外側 0.075 Å の位置は白い背景になった。同じ三角形を CueMol の writer から POV-Ray で描くと、その位置は黒だった。開いた外周では、画面に投影した辺に垂直な外向きへ中心をずらし、§4 の線幅テストにこの傾きを加えたい。[計画 §2.3 の押し出し方向](edge-object-space-completion.md#L214)・[計画 §4 の線幅テスト](edge-object-space-completion.md#L342)

**§2.3 では、開いた mesh の鋭い凸角で、外向きにずらした2辺の端を丸くつなぐ。** 頂角30度の不透明な三角形を正面から見て、`eglinew = 0.10 Å` とした。計画どおり辺ごとに外向きに 0.05 Å ずらして Umbreon で描くと、頂点から約 0.053 Å 先では中央が白く、両脇が黒くなり、先端が二股に見えた。同じ三角形を CueMol の writer から POV-Ray で描くと3画素とも黒だった。§4 の外周テストに、鋭角の二等分線上で先端のすぐ外側も線色になることを加えたい。[計画 §2.3 の外向きの変位](edge-object-space-completion.md#L226)・[計画 §4 の外周テスト](edge-object-space-completion.md#L389)

## 6. mesh の輪郭が手前の不透明な面を越えないようにする

§2.1 で維持する `camBias` は、輪郭を平均辺長の15%以上だけ視点側へ動かす。薄い閉じた mesh を緑の不透明な板で完全に覆った試験では、半径 0.005 Å の黒線が 0.171 Å 手前に移動し、板の上に現れた。`camBias` だけを無効にすると同じ画素は板の緑に戻った。POV-Ray writer は線を法線方向に持ち上げており、この平均辺長に応じた視点方向の変位は加えていない。補正量に線半径に応じた上限を設け、通常の `edges` モードで、本体を完全に覆う板が輪郭線も隠すことを確認したい。[計画 §2.1](edge-object-space-completion.md#L130)・[補正量の計算](../../src/umbreon/edges/mesh_feature_edges.cpp#L451)

## 7. 通常の edges では、手前の半透明な立体を通して奥の輪郭が見えるようにする

不透明な緑の球を、別 renderer の白い球（色の alpha 0.2）で包むと、現行の Umbreon では内側の球本体は透けて見えるのに、その黒い輪郭は96線分すべてが切り落とされた。CueMol の POV-Ray writer では外球の有無によらず内球に同じ20本の輪郭を出力した。その出力を POV-Ray で描くと、外球越しの同じ画素は輪郭ありで RGB (130, 130, 130)、輪郭なしで (253, 253, 253) となり、輪郭が見えた。通常の `edges` で別 renderer の半透明な立体が手前にある場合は今回の修正対象とし、奥の線を生成した上で描画時に透過合成したい。[計画 §2.4](edge-object-space-completion.md#L226)・[球と円柱の内外判定](../../src/umbreon/edges/object_space_edges.cpp#L120)

## 8. 原子間相互作用の `flat` 末端の輪郭欠けは従来経路と同じため保留する

原子間相互作用の `flat` 末端と同じ `DisplayContext::cylinder()` 呼び出しで、球を置かずに円柱を視線に対して45度傾けた。CueMol の POV-Ray writer が出力した輪郭は側線2本で、POV-Ray 画像でも端の外周は緑の本体から白い背景に直接切り替わった。このケースは Umbreon と一致する。端面を明示的に作る `cylinderCap()` を同じ配置で別途試すと、writer は22線分を出力し、端面の外周が黒く描かれた。明示的な端面に対する Umbreon との差は、`flat` 末端とは区別して扱う。球付き stick の接合部は計画 §2.5 の確認対象とする。[円柱の輪郭生成](../../src/umbreon/edges/analytic_silhouette.cpp#L151)・[計画 §2.5](edge-object-space-completion.md#L237)

## 9. slab で手前の遮蔽物が切れたとき、奥の球の輪郭を残す

通常の `edges` モードで、半径 1 Å の球を別 renderer の半径 1.6 Å の不透明な球で包み、手前のクリップ面で外球の前面を切った。CueMol の writer から POV-Ray で描画すると、内球の外周にある同じ画素は輪郭オンで黒、オフで灰色になった。Umbreon では、線の生成時に「外球の内側」と判定して内球の輪郭を48線分すべて捨てた。比較のため事前の切り落としだけを無効にすると、同じ位置に黒線が出た。[計画 §2.4](edge-object-space-completion.md#L239)・[立体の内外判定](../../src/umbreon/edges/object_space_edges.cpp#L120)

別 renderer の遮蔽物が手前のクリップ面にかかる場合は、内球の輪郭を生成し、どの区間が見えるかは本体の主光線に任せたい。§4 では、同じ配置で slab を動かし、外球の前面が内球の輪郭を覆うときは線が隠れ、前面が切れると元の輪郭が見えることを確認する。球・stick の接合部には引き続き §2.4 の内外判定を使う。[計画 §2.8 の slab](edge-object-space-completion.md#L314)・[本体の主光線のクリップ処理](../../src/umbreon/shading/transparency.hpp#L368)

## 10. ワイヤー線から変換した円柱を輪郭抽出の対象から外す

`SimpleRenderer` のワイヤー結合や簡易表示の距離線は `startLines()` で描く。緑の線を1本出力した試験では、CueMol の POV-Ray writer は線本体の円柱を1本だけ出し、POV-Ray 画像は edge のオン・オフで全画素が一致した。Umbreon exporter はワイヤー線を通常の円柱に変換するため、object-space の抽出器に渡すと両側に黒い輪郭が1本ずつ追加された。§2.2 では線描画命令に由来する円柱を識別し、輪郭の生成対象から外したい。そうすれば、同じ renderer の stick には指定どおり輪郭を付けられる。[計画 §2.2](edge-object-space-completion.md#L169)・[円柱の輪郭抽出](../../src/umbreon/edges/analytic_silhouette.cpp#L204)

**ワイヤー由来の円柱は、stick の輪郭を事前に切る立体からも外す。** 同じセクションで、黒い輪郭を持つ不透明な stick の少し奥に赤いワイヤーを置いた。CueMol の writer はワイヤーの有無にかかわらず同じ側線を2本出力し、POV-Ray では重なる位置も黒だった。Umbreon でワイヤー自身の輪郭生成だけを止めると、`insideAnySolid()` が手前の側線を切り、その画素は赤くなった。切り落としからワイヤーを外し、描画時の遮蔽を本体の主光線に任せると黒に戻った。§2.2 のワイヤー識別フラグを、§2.4 の総当たり判定と切り落とし用 BVH の登録にも使いたい。[計画 §2.2](edge-object-space-completion.md#L181)・[計画 §2.4](edge-object-space-completion.md#L253)・[立体の内外判定](../../src/umbreon/edges/object_space_edges.cpp#L120)

## 以前のレビューで確認した事項

- **renderer 間の境界線**はセクションごとに抽出する。線を無効にした renderer B の三角形を renderer A の三角形に接続すると、POV-Ray 出力では A の3辺が残り、現行の Umbreon では2辺になる。計画にはセクション内での頂点統合・辺の隣接判定と、この配置での回帰テストが入っている。[計画 §2.2](edge-object-space-completion.md#L153)・[テスト条件](edge-object-space-completion.md#L282)
- **完全透明の立体**は球・円柱の輪郭を切る際の遮蔽物から除く。別セクションの完全透明な球で包んだ場合は、内球の輪郭が残ることを確認する。同じセクションで包むと、POV-Ray writer でも内球の不透明な輪郭は外球なしで20本、外球ありで0本だった。この配置は従来経路でも起きるため、追加の修正要件には含めない。透明面の深度が背後の物体の fog を変える現象は、edge を無効にしても再現するため、計画 §2.8 のとおり共通の fog 処理の別課題とする。[透明な球のテスト条件](edge-object-space-completion.md#L304)・[fog の対象範囲](edge-object-space-completion.md#L249)
- **輪郭線の色**は、直接光・環境光・影・AO・GI に左右されず、指定 RGB を合成に渡す。半透明・AA・fog は通常どおり適用する。環境光を灰色にして AO・GI を切り替え、不透明な線が覆う画素の指定色を確認する。[計画 §2.6](edge-object-space-completion.md#L220)・[線色のテスト条件](edge-object-space-completion.md#L310)
