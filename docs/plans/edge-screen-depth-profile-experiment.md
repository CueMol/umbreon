# 回転中に SES の短い輪郭が出入りする原因を調べる実験計画

## 最初に答える問い

3CHY の同じ場所で線が出たフレームと前後のフレームを取り、**その線を横切ると、実際に最初に見える面の奥行きが跳ぶか**を測る。変える量は二つある。まず三角形を固定してレイの間隔だけを狭め、次に十分細かいレイの間隔を固定して元の原子から SES を細かく作り直す。両方で段差が残り、線だけが点滅する箇所では、Umbreon が段差を線にするどの段階で出力が変わったかを追う。

この順序なら、具体的な修正候補を「追加レイを打つ」「表面メッシュ生成を見直す」「分類または線の接続を直す」まで絞れる。各地点の観測が区別を許さない場合は未判定で終了する。実験の数値は本番の edge 判定に導入するしきい値ではない。

## 3. 固定メッシュ上の深度断面を取る

**計測の実装場所。** 隔離した Umbreon の `src/umbreon/render/embree_renderer.cpp` で、Embree シーン、`ShadeContext`、カメラ基底が揃った所から、明示的に指定した断面だけを 1 フレームにつき一度測る。適応 AA の有無に左右される画素ループの外に置く。`storeProbeGBuf` と同じ投影式を用い、`src/umbreon/shading/transparency.hpp` の `probeGBuffer` で一次レイの最初の hit を得る。診断用に同じ交差の `geomID` と `primID`、hit/miss、必要ならワールド hit 位置を返せるようにする。出力の奥行きは既存の `viewZ = tfar * dot(rd,camDir)`（Å）。PNG や既存の深度バッファを補間しても新しい交差は得られない。

- `sites.csv` を入力にし、列を `scene,frame,site,cx,cy,tx,ty,half_length_px` とする。`c` は断面の中心、`t` は画像上で枝に沿う単位接線。最初の 2 地点は前節の中心と向きから始め、局所画像を拡大して確定する。枝が消えたフレームも対応する断面を残す。
- 出力画像の左上端を (0,0)、最初の画素中心を (0.5,0.5) とする。法線 `n=(-ty,tx)` を用い、`p=c+s*n`、`−4 ≤ s ≤ 4` 出力 px。連続座標から `u=2*p.x/Wout−1, v=1−2*p.y/Hout` を得て、実際の正射影・透視投影のレイ生成式に渡す。ここで再び 0.5 を足さない。supersample 倍率も掛けない。
- 深度を 1/128 px 格子上で一度取得する（8 px 幅で 1,025 本）。そこから `h=1/4, 1/16, 1/64` px の各系列を切り出す。開始点は各々 `−4` と `−4+h/2` の 2 位相。解像度ごとにフル画面を描き直す必要はない。
- `profiles.csv` に `scene,frame,detail,site,s,x,y,hit,viewZ,geomID,primID,objectId,normal,clipCut,clipNearVz,clipFarVz,surfAlpha` を保存する。miss の深度は空欄。hit/miss の境界、clip 面、透過面は別記する。二つの通常の hit がある枝だけを次節の段差比で判定する。同一物体の自己遮蔽はあり得る。三角形 ID の変化だけでは段差とみなせない。

実装する診断入口は環境変数 `UMBREON_PROFILE_SITES`（そのフレーム用に絞った CSV）と `UMBREON_PROFILE_OUT`（その描画専用の出力 CSV）とする。ドライバが scene・frame・detail ごとに別ファイルを割り当ててから隔離した CueMol プロセスを起動する。フレームをまたぐ GUI の現在状態に頼らず、保存したカメラを読み、その姿勢を 1 回描画して終了する。解析スクリプトが最後に各 CSV を連結する。これらの変数・ドライバは本計画で新設するもの。

**計測器の受入試験。** 実シーンの hi-res 画素中心を出力座標へ換算して同じレイを打ち、既存 G-buffer と hit/miss、viewZ、clip 状態が一致するか確認する。加えて正射影で 1 px = 1 Å とし、次のモデルを同じ計測器で通す。

| 形状 | 期待する隣接サンプル深度差の最大値 |
|---|---|
| 視線方向が +z で、`z=100+1.5x` の平面 | 1/4、1/16、1/64 px で順に 0.375、0.09375、0.0234375 Å |
| 全域に `z=102` の背面、`x<0.37` の範囲だけに `z=100` の前面 | どの間隔・位相でも 2 Å。検出位置をはさむ区間に x=0.37 が入る |

対照モデルでは中心 (s=0) が x=0 を通り、+s が +x を向くよう配置する。平らな正面板も測って数値ノイズを取り、解析式との誤差が `max(16 ULP(viewZ), 10⁻⁴ Å)` を超える場合、座標規約・深度・レイ生成を先に直す。

## 4. 同じ枝について二種類の収束を判定する

**A. レイ間隔への依存。** 断面図に各サンプルの `viewZ(s)` を描く。目的の枝を囲む探索区間を元画像と最細断面上で決め、他の枝・主線を除き、全間隔で共通に使う。区間内で `G(h)=max |z(s+h)−z(s)|` とその位置を記録する。同程度の候補が複数あり対応づけられなければ区間を分ける。実験上の仮判定は以下とする。

- 2 位相とも `G(1/64)/G(1/16) ≥ 0.8`、ピークの移動が 0.25 px 以内、差が正面板の誤差と 16 ULP の大きい方を十分超える（10 倍以上）場合は「このメッシュでは段差を支持」。深度図で同じ位置の両側にそれぞれ面が続くことも確認する。
- 2 段階の細分化でいずれも `G(h/4)/G(h) ≤ 0.4`、両位相で連続した傾斜が見えれば「この範囲では連続面を支持」。一定深度で全差がノイズ以下なら「段差を分解できず」とする。
- それ以外、特に接線近く・枝先で段差がゼロに近い箇所は、断面を接線方向に ±1 px ずらし、対象部分だけ 1/256 px（半位相も取得）まで一度精査する。なお分離できなければ未判定。有限個のレイで数学的な不連続を証明したとは扱わない。

**B. メッシュ生成への依存。** 同じ原子座標・選択・半径・`proberad`・`meshms` で、CueMol2 の `dsurface.detail` だけを変えて SES を再生成する。基準の実効値が既定の 6 なら **6 → 16 → 36**。detail 36 は三角形数が基準のおよそ 16 倍になる見込みなので、先に 1 回だけ生成時間とメモリを測り、重すぎれば 6 → 12 → 24 に落とす。現在の `DirectSurfRenderer.cpp` の `detailToVoxelSize` では基準長が 0.50 → 0.25 → 0.125 Å となる。MeshMS が実際に使う `mesh_size` には係数と下限がある。既定以外なら同じ式で基準長が各段およそ半分になる整数を選ぶ。既存三角形を平面内で細分割しても比較にならない。

1. 各 detail で生成ログのアルゴリズム名、実効 `mesh_size`、頂点・面数、Umbreon に渡る頂点座標と面インデックスのハッシュ、対象周辺の三角形辺長の中央値を記録する。distfield へのフォールバック、予算制限で実効サイズが変わらない場合はその段を比較から外す。
2. A で収束を確認した同じレイ間隔と位相を全メッシュで使用する。各フレームのカメラは固定する。メッシュ間で枝が動き得るので、元の断面と、枝を追って移動した断面の両方を保存する。初期位置の周囲 ±4 px を接線方向 1 px 間隔の平行断面で走査し、必要時は ±8 px に広げる。枝の向き、前後の面の順序、近傍の主線との接続を照合する。異なるメッシュ間では三角形 ID を対応条件にしない。
3. `summary.csv` に各段の段差（Å）、枝の位置ずれ（px）、確認できた長さ（px）、対応可否を書く。細かい 2 段で同一枝が見つかり、位置差 ≤1 px、胴部の段差差 ≤20% を安定の目安とする。枝先は長さと終端の移動を別に評価する。粗い段でだけ見つかった場合、細かい 2 段の探索域を比較図で確認して初めて「メッシュ依存を支持」とする。枝の移動と消失を区別できない場合は未判定。

## 5. 判断から次の実装に進む条件

| 観測 | 次に試す実装・確認 |
|---|---|
| 粗い画素ペアでは段差に見え、固定メッシュの細かい断面では連続面となる | 候補ペアだけに中点・四分点のレイを追加する試作。密な断面を参照に、少数レイで急斜面の誤検出を除けるか、既知の本物の輪郭を失わないかを測る |
| 固定メッシュには段差があり、SES を再生成して細かくすると枝が消えるか形が収束しない | CueMol2 の MeshMS 生成側を調査する。枝の近傍メッシュと断面を重ね、幾何で消える現象を screen の法線しきい値で抑える修正は保留する |
| 細かい 2 メッシュで枝が安定し、点滅の前後にも段差がある | 下記の段階別ログで最初の欠落を特定し、その段だけを対象に試作する |
| メッシュを細かくしても、追加レイが中央フレームだけに実際の遮蔽または clip 境界を捉える | 中間角度を測って可視区間を確かめる。瞬間的に見える線を抑える必要があれば描画方針として判断する |
| 参照断面が分解能・位相で一致しない、枝の対応が取れない | 結論を保留し、不一致の断面と画像を残す。この結果だけでは方式を選ばない |

**段階別ログ（深度断面より先に、段①から実行する）。** 段①は既存の一時 dump を拡張すれば得られる。`UMBREON_SCREEN_EDGE_MEASURE` は既に境目ごとの段差・1 px 外挿差・法線の違い・厚み・採否を CSV に出し、`UMBREON_SCREEN_EDGE_DUMP` は分類結果の格子（PPM）と viewZ を出す。これに、2 px 段差判定の結果、平均した法線の違い、実際に使ったしきい値、NMS の採否を足す。`screen_edge_classify.cpp` と `screen_vector_edges.cpp` で、基準フレームとその前後の同じ ROI について、①元 G-buffer の横・縦ペアと、内部格子で 1 マス・2 マス離れた候補、外挿残差、しきい値と NMS 採否、②分類後の格子辺、③最初の trace、④ `pruneWeakChains` 後の chain、⑤ rasterize した線の被覆、⑥ fog・色・縮小を含む最終 RGB を対応づける。ROI の外まで延びる chain では全体を追跡し、表示だけを切り抜く。各段の座標を出力 px に統一して独立に測った断面と重ねる。「段差は残り、中央フレームだけ段②で候補が消える」と「段②にはあり、段④で枝が消える」では修正箇所が違う。被覆が安定して RGB の赤画素数だけが動く場合は画像検出器のイベントとして扱う。

## 最小実行と完了条件

最初に、2 地点 × 3 フレームで段階別ログの段①〜②だけを取る（描画 6 回、計測器の新設なし）。`n_ds` 008 が §0 の仮説どおりしきい値の越え方で説明できれば、その地点の深度断面は省く。次に、残った地点について **3 フレーム × 基準メッシュ**と合成対照で A を実行する。次に同じ 6 ケースに細かいメッシュ 2 段を追加する。固定された 1 断面だけなら合計 18 × 1,025 = 18,450 本の一次レイで、平行断面・対照・通常の画像生成は別。既知の問題角度に対して回転全体を細かく刻む必要はない。0.1° の間で本当に遮蔽が発生した疑いが残る地点だけ 0.05°、次に 0.025° で挟む。

成果物は元シーンと入力ハッシュ、実効設定・カメラ・ビルド識別子、`sites.csv`、`profiles.csv`、`summary.csv`、地点ごとの「前／当該／後の拡大画像＋測線＋深度曲線」、必要箇所の段階別ログ。各地点に、観測が支持する原因、反証する観測、未判定の要素を 1 行ずつ書く。画像・CSV はターミナルから使える絶対パスで掲載する。

修正の試作に進めるのは、合成対照と基準画像の再現が通り、少なくとも 1 地点で修正すべき段階を観測できた場合。候補が得られた後に、レポートの円柱底面、mesh4 の粗・細、SES の T 字を静止画で、1IYE の ribbon（線幅 0.1 Å）を既知の点滅フレームと元の 0.5° 刻み 180 フレームで再評価する。枝が短くなったり円柱底面に帯が戻れば、イベント件数が減っても採用を見送る。
